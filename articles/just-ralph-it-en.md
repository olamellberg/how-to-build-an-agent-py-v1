# Just Ralph-it
**Version 1.0** | 2026-01-22
### Let the AI do the work in an infinite loop

**Credit:** The Ralph method was created by [Geoffrey Huntley](https://x.com/GeoffreyHuntley). This article is a brief summary — for the complete guide, see [The Ralph Playbook](https://github.com/ghuntley/how-to-ralph-wiggum) on GitHub.

"Ralph Wiggum Technique" is a development methodology where you let an AI agent work autonomously in an infinite loop. Instead of micromanaging the agent step by step, you set up the right structure — and then let the agent run until the job is done.

The idea is simple: **eventual consistency through iteration**. The agent may make mistakes, but with the right feedback loop (tests, linters, build), it self-corrects — over and over — until everything works.

---

## The Concept: Three phases, one loop

The Ralph method follows a simple workflow:

1. **Define requirements** — Discuss with the LLM what you want to build. Break down into "Jobs to Be Done" (JTBD). Write specifications in `specs/*.md`.

2. **Plan** — Run the loop in "planning mode" to generate an `IMPLEMENTATION_PLAN.md` with prioritized tasks.

3. **Build** — Run the loop in "build mode". The agent picks a task from the plan, implements, runs tests, commits — and starts over with the next one.

> **Key insight:** Each loop iteration starts with a fresh context window. The agent reads the same files every time (`PROMPT.md` + `AGENTS.md`), picks the next task from the plan, and works focused on *one* thing.

---

## The basic loop

In its simplest form, Ralph is just a bash loop:

```bash
while :; do cat PROMPT.md | claude ; done
```

That's it. The loop runs the agent, the agent reads the prompt, implements the next task, commits, and exits. The bash loop restarts immediately — with a fresh memory.

### Example: Enhanced loop with mode selection

```bash
#!/bin/bash
# Usage: ./loop.sh [plan] [max_iterations]

if [ "$1" = "plan" ]; then
    MODE="plan"
    PROMPT_FILE="PROMPT_plan.md"
else
    MODE="build"
    PROMPT_FILE="PROMPT_build.md"
fi

while true; do
    cat "$PROMPT_FILE" | claude -p \
        --dangerously-skip-permissions \
        --model opus
    
    git push origin "$(git branch --show-current)"
    
    echo "======================== LOOP COMPLETE ========================"
done
```

> **Important: Sandboxing**  
> `--dangerously-skip-permissions` bypasses all permission prompts. Always run in an isolated environment (Docker, VM, or similar) with minimal credentials. "It's not if it gets popped, it's when."

## Key Principles

### 1. Context is everything

An LLM has limited "working memory" (context window). Ralph maximizes this by:

- **Keeping tasks small** — one task per loop iteration
- **Clearing context** — each iteration starts from scratch
- **Using subagents** — delegate exploratory work to avoid polluting the main context

### 2. Backpressure via tools

The agent is steered by feedback from real tools:

- **Tests** — must pass before commit
- **Linters/formatters** — automatic style enforcement
- **Build** — the code must compile

If something fails, the agent iterates until it works. This is "backpressure" — tools pushing back against bad code.

### 3. Let Ralph Ralph

Trust the agent to self-correct. Your role is to:

- **Observe** — see what patterns emerge, where the agent goes wrong
- **Adjust structure** — update `PROMPT.md` or `AGENTS.md` when you see recurring problems
- **Trust the loop** — give the agent time to self-correct

> "Eventual consistency achieved through iteration."

## File structure

A typical Ralph project looks like this:

```
project-root/
├── loop.sh                    # Ralph loop script
├── PROMPT_build.md            # Instructions for build mode
├── PROMPT_plan.md             # Instructions for plan mode
├── AGENTS.md                  # How to build/run the project
├── IMPLEMENTATION_PLAN.md     # Prioritized task list
├── specs/                     # Requirements specifications
│   ├── feature-1.md
│   └── feature-2.md
└── src/                       # Source code (generated by agent)
```

### PROMPT_build.md (example)

```markdown
# Build Mode

You are a code-editing agent. Your task:

1. Read IMPLEMENTATION_PLAN.md
2. Pick the next task (the first one not marked as done)
3. Implement the task
4. Run tests: `npm test`
5. If tests pass: commit with descriptive message
6. If tests fail: fix and try again

Rules:
- Only change files needed for current task
- Follow code style in existing code
- Commit often, small commits
```

### AGENTS.md (example)

```markdown
## Commands
- Build: `npm run build`
- Test: `npm test`
- Lint: `npm run lint`

## Structure
- src/: source code
- tests/: tests
- specs/: requirements

## Stack
- Node.js 20
- TypeScript 5.x
```

## Get started

1. **Set up the project:**
   ```bash
   mkdir ralph-project
   cd ralph-project
   git init
   ```

2. **Create `PROMPT_build.md` and `AGENTS.md`** (see examples above)

3. **Run the loop:**
   ```bash
   chmod +x loop.sh
   ./loop.sh build
   ```

4. **Observe and adjust:**
   - See what patterns emerge
   - Update `PROMPT_build.md` when you see recurring problems
   - Trust the agent to self-correct

---

## Why it works

Ralph works because:

1. **Fresh memory each iteration** — the agent only sees what's needed
2. **Deterministic feedback** — tests and build give clear signals
3. **Eventual consistency** — with enough iterations, the system converges to "done"
4. **Autonomy** — you don't need to micromanage every step

It's not perfect. It's not fast. But it's *automatic* — and that's the power.
