Just Ralph-it

Låt AI:n göra jobbet i en oändlig loop Let the AI do the work in an infinite loop

Credit

Ralph-metoden är skapad av Geoffrey Huntley. Denna artikel är en kortfattad sammanfattning — för den fullständiga guiden, se The Ralph Playbook på GitHub. The Ralph method was created by Geoffrey Huntley. This article is a brief summary — for the complete guide, see The Ralph Playbook on GitHub.

"Ralph Wiggum Technique" är en utvecklingsmetodik där du låter en AI-agent arbeta autonomt i en oändlig loop. Istället för att mikromanagera agenten steg för steg, sätter du upp rätt struktur — och låter sedan agenten köra tills jobbet är klart. "Ralph Wiggum Technique" is a development methodology where you let an AI agent work autonomously in an infinite loop. Instead of micromanaging the agent step by step, you set up the right structure — and then let the agent run until the job is done.

Idén är enkel: eventual consistency genom iteration. Agenten kan göra misstag, men med rätt feedback-loop (tester, linters, bygge) korrigerar den sig själv — om och om igen — tills allt fungerar. The idea is simple: eventual consistency through iteration. The agent may make mistakes, but with the right feedback loop (tests, linters, build), it self-corrects — over and over — until everything works.

Konceptet: Tre faser, en loop The Concept: Three phases, one loop

Ralph-metoden följer ett enkelt arbetsflöde: The Ralph method follows a simple workflow:

  1. Definiera kravDefine requirements — Diskutera med LLM:en vad du vill bygga. Bryt ner i "Jobs to Be Done" (JTBD). Skriv specifikationer i specs/*.md. — Discuss with the LLM what you want to build. Break down into "Jobs to Be Done" (JTBD). Write specifications in specs/*.md.
  2. PlaneraPlan — Kör loopen i "planning mode" för att generera en IMPLEMENTATION_PLAN.md med prioriterade uppgifter. — Run the loop in "planning mode" to generate an IMPLEMENTATION_PLAN.md with prioritized tasks.
  3. ByggBuild — Kör loopen i "build mode". Agenten plockar en uppgift från planen, implementerar, kör tester, committar — och börjar om med nästa. — Run the loop in "build mode". The agent picks a task from the plan, implements, runs tests, commits — and starts over with the next one.
Nyckelinsikt: Varje loop-iteration startar med rent kontextfönster. Agenten läser samma filer varje gång (PROMPT.md + AGENTS.md), väljer nästa uppgift från planen, och arbetar fokuserat på en sak. Key insight: Each loop iteration starts with a fresh context window. The agent reads the same files every time (PROMPT.md + AGENTS.md), picks the next task from the plan, and works focused on one thing.

Den grundläggande loopen The basic loop

I sin enklaste form är Ralph bara en bash-loop: In its simplest form, Ralph is just a bash loop: 

while :; do cat PROMPT.md | claude ; done

Det är allt. Loopen kör agenten, agenten läser prompten, implementerar nästa uppgift, committar, och avslutar. Bash-loopen startar om direkt — med rent minne. That's it. The loop runs the agent, the agent reads the prompt, implements the next task, commits, and exits. The bash loop restarts immediately — with a fresh memory.

Exempel: Utökad loop med mode-val Example: Enhanced loop with mode selection 

#!/bin/bash
# Usage: ./loop.sh [plan] [max_iterations]

if [ "$1" = "plan" ]; then
    MODE="plan"
    PROMPT_FILE="PROMPT_plan.md"
else
    MODE="build"
    PROMPT_FILE="PROMPT_build.md"
fi

while true; do
    cat "$PROMPT_FILE" | claude -p \
        --dangerously-skip-permissions \
        --model opus
    
    git push origin "$(git branch --show-current)"
    
    echo "======================== LOOP COMPLETE ========================"
done
Viktigt: Sandboxning Important: Sandboxing

--dangerously-skip-permissions kringgår alla behörighetsfrågor. Kör alltid i en isolerad miljö (Docker, VM, eller liknande) med minimala credentials. "It's not if it gets popped, it's when." --dangerously-skip-permissions bypasses all permission prompts. Always run in an isolated environment (Docker, VM, or similar) with minimal credentials. Nyckelprinciper Key Principles

1. Kontext är allt 1. Context is everything

En LLM har begränsat "arbetsminne" (context window). Ralph maximerar detta genom att: An LLM has limited "working memory" (context window). Ralph maximizes this by:

  • Hålla uppgifter små — en uppgift per loop-iteration Keeping tasks small — one task per loop iteration
  • Rensa kontexten — varje iteration startar från scratch Clearing context — each iteration starts from scratch
  • Använda subagenter — delegera utforskande arbete för att inte förorena huvudkontexten Using subagents — delegate exploratory work to avoid polluting the main context

2. Backpressure via verktyg 2. Backpressure via tools

Agenten styrs av feedback från verkliga verktyg: The agent is steered by feedback from real tools:

  • Tester — måste passera innan commit Tests — must pass before commit
  • Linters/formatters — automatisk stilkontroll Linters/formatters — automatic style enforcement
  • Bygge — koden måste kompilera Build — the code must compile

Om något fallerar, itererar agenten tills det fungerar. Detta är "backpressure" — verktyg som trycker tillbaka mot dålig kod. If something fails, the agent iterates until it works. This is "backpressure" — tools pushing back against bad code.

3. Let Ralph Ralph 3. Let Ralph Ralph

Lita på att agenten självkorrigerar. Din roll är att: Trust the agent to self-correct. Your role is to:

  • Observera — se vilka mönster som uppstår, var agenten går fel Observe — see what patterns emerge, where the agent goes wrong
  • Justera — lägg till "skyltar" (instruktioner i prompten, utilities i koden) Adjust — add "signs" (instructions in the prompt, utilities in the code)
  • Regenerera planen — om agenten går i cirklar, kasta planen och börja om Regenerate the plan — if the agent goes in circles, throw out the plan and start over

Filstruktur File Structure

Ett typiskt Ralph-projekt ser ut så här: A typical Ralph project looks like this: 

project-root/
├── loop.sh                    # Ralph loop-skript
├── PROMPT_build.md            # Instruktioner för build mode
├── PROMPT_plan.md             # Instruktioner för plan mode
├── AGENTS.md                  # Hur man bygger/kör projektet
├── IMPLEMENTATION_PLAN.md     # Prioriterad uppgiftslista (genereras)
├── specs/                     # Kravspecifikationer
│   ├── feature-a.md
│   └── feature-b.md
└── src/                       # Applikationskod

PROMPT_build.md

Instruktioner som agenten läser varje iteration. Exempel på nyckelpunkter: Instructions the agent reads every iteration. Example key points:

  • "Studera specs/* för att lära dig specifikationerna""Study specs/* to learn the specifications"
  • "Välj den viktigaste uppgiften från IMPLEMENTATION_PLAN.md""Choose the most important task from IMPLEMENTATION_PLAN.md"
  • "Sök i koden innan du antar att något inte finns implementerat""Search the codebase before assuming something isn't implemented"
  • "Kör tester efter implementation""Run tests after implementation"
  • "När testerna passerar, committa och pusha""When tests pass, commit and push"

AGENTS.md

En kort guide för hur man bygger och kör projektet. Håll den kort (~60 rader) — detta laddas i varje iteration. A short guide on how to build and run the project. Keep it brief (~60 lines) — this is loaded in every iteration.

IMPLEMENTATION_PLAN.md

Genereras av agenten i "plan mode". En prioriterad lista med uppgifter som agenten arbetar igenom. Planen är "disposable" — om den blir fel, kasta den och generera en ny. Generated by the agent in "plan mode". A prioritized list of tasks the agent works through. The plan is disposable — if it goes wrong, throw it out and generate a new one.
