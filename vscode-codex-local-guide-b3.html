VSCode + Codex Local:
Från noll till agentisk utveckling

En komplett hands-on guide för fullstack-utvecklare som vill komma igång med OpenAI:s kodningsagent — direkt i editorn, med ChatGPT Business-licensen ni redan betalar för.

Publicerad februari 2026 · Verktyg: Codex IDE Extension + CLI · Senaste modell: GPT-5.3-Codex
1

Varför Codex Local, och varför nu?

Kontext

Andrej Karpathy sammanfattade det nyligen: han gick från 80 % manuell kodning till 80 % agentkodning på bara några veckor. Det är inte längre en fråga om huruvida AI-agenter förändrar utvecklaryrket — utan om hur snabbt du anpassar dig.

OpenAI:s Codex är deras svar på den agentiska utvecklingsvågen. Det är inte samma Codex som 2021 — det är en helt ombyggd kodningsagent som kan läsa, redigera och köra kod. Med Codex Local i VSCode-extensionen sker allt på din maskin, i ditt projekt, med din sandbox. Och det ingår redan i ChatGPT Business.

Vad gör Codex Local unikt?

  • Lokal exekvering — agenten kör kommandon i din terminal, inte i molnet
  • Sandbox-isolering — filsystemskrivningar och nätverksåtkomst blockeras utanför workspace
  • AGENTS.md — styrdokument som ger agenten projektspecifik kontext och regler
  • Mid-turn steering — du kan omdirigera agenten medan den arbetar (nytt feb 2026)
  • Skills-system — installerbara färdighetspaket som utökar agentens kapacitet
Egenskap Codex Local (VSCode) Codex Cloud
Exekvering Din maskin, din terminal OpenAI:s sandbox-miljö
Filåtkomst Ditt lokala filsystem Klonat repo i molnet
Nätverksåtkomst Blockerat i Agent mode Konfigurerbart
Latens Låg (lokal I/O) Högre (nätverksbaserat)
Parallella tasks En åt gången Multipla parallella
Bäst för Iterativ daglig utveckling Större bakgrundsjobb

Installation & setup

Förberedelse

Codex IDE-extensionen finns tillgänglig för macOS, Linux och Windows (experimentellt, WSL rekommenderas). Den fungerar med VSCode, Cursor, Windsurf och andra VSCode-kompatibla editorer.

Plattform Support Kommentar
macOS (Apple Silicon / Intel) ✅ Full Även Codex Desktop-app tillgänglig
Linux (Ubuntu/Debian/Arch) ✅ Full Landlock-sandbox, Bubblewrap experimentellt
Windows (nativt) ⚠️ Experimentellt AppContainer-sandbox, begränsad filskydd
Windows + WSL2 ✅ Rekommenderat Bästa Windows-upplevelsen

Steg-för-steg: VSCode-extensionen

1

Installera extensionen

Öppna Extensions-panelen i VSCode (Ctrl+Shift+X), sök "Codex" och installera Codex — OpenAI's coding agent av OpenAI. Alternativt via Marketplace-länk eller kommandorad.

Bash Terminal 
# Installera extensionen från kommandorad (valfritt)
code --install-extension openai.chatgpt

# Starta om VSCode efteråt
code .
2

Logga in med ChatGPT-kontot

Klicka på Codex-ikonen i sidofältet och välj "Sign in with ChatGPT". Webbläsaren öppnas för OAuth. Er ChatGPT Business-admin kan styra åtkomst via RBAC.

3

Öppna ett projekt

Codex kräver att du har en mapp öppen. Öppna ert repo med File → Open Folder eller code ~/projects/mitt-projekt.

4

Verifiera att det fungerar

Skriv ett enkelt meddelande i Codex-panelen, t.ex. Beskriv projektstrukturen i denna mapp. Agenten ska läsa filerna och svara.

💡

Windows-användare: Undvik att arbeta under /mnt/c/ i WSL — flytta repot till ~/code/ för bättre I/O-prestanda. Installera Node via nvm i WSL-skalet: nvm install 22.

Alternativ: Codex CLI (terminalbaserat)

Om du föredrar terminalen, eller vill använda Codex i CI/CD-pipelines:

Bash Terminal — Installation 
# Via npm (rekommenderat)
npm install -g @openai/codex

# Via Homebrew (macOS)
brew install openai-codex

# Logga in och starta
codex
# Välj "Sign in with ChatGPT" vid prompten

# Kontrollera status och kvarvarande limits
codex
# I TUI:n: /status

AGENTS.md — ge agenten projektkontext

Konfiguration

AGENTS.md är Codex motsvarighet till Cursor's .cursorrules eller Claude Code's CLAUDE.md. Det är en markdown-fil som agenten läser innan den börjar arbeta. Här definierar du projektets normer, testkommandon och konventioner. Det är den enskilt viktigaste filen att skapa för att få kvalitativt output.

Hur Codex upptäcker AGENTS.md

Codex bygger en instrukteringskedja vid sessionsstart. Filerna läses i prioriteringsordning:

  • Globalt: ~/.codex/AGENTS.md (eller AGENTS.override.md)
  • Projektrot: AGENTS.md i Git-roten
  • Per katalog: Nested AGENTS.md nedåt till aktuell arbetskatalog

Override-filer (AGENTS.override.md) vinner alltid över AGENTS.md i samma katalog.

Markdown AGENTS.md — Exempelfil för ett fullstack-projekt 
# AGENTS.md

## Projektöversikt
Detta är en Next.js 15 fullstack-applikation med TypeScript,
Prisma ORM och PostgreSQL. Frontend använder Tailwind CSS.

## Arbetsregler
- Kör alltid `pnpm lint` innan du presenterar ändringar.
- Kör `pnpm test` efter alla ändringar i src/lib/.
- Fråga innan du lägger till nya production dependencies.
- Skriv alla commit-meddelanden på engelska.
- Föredra server components framför client components.

## Testning
- Enhetstester: `pnpm test`
- E2E: `pnpm test:e2e` (kräver nätverksåtkomst)
- Typkontroll: `pnpm typecheck`

## Kodstandard
- Använd zod för alla API-valideringar.
- Error handling med custom AppError-klass i src/lib/errors.ts.
- Alla API-routes under src/app/api/ ska ha rate limiting.

## Katalogstruktur
- src/app/       → Next.js App Router pages
- src/lib/       → Shared utilities, DB-klient
- src/components/ → React-komponenter
- prisma/        → Schema och migrationer
💡

Nested overrides: Lägger ni en AGENTS.override.md i t.ex. services/payments/, kan ni ge separata regler för känsliga moduler — utan att ändra projektrotens standarder.

Avancerat: config.toml

CLI:n och IDE-extensionen delar konfigurationsfilen ~/.codex/config.toml. Här sätter ni default-modell, sandbox-policy, MCP-servrar med mera.

TOML ~/.codex/config.toml 
# Standardmodell för alla sessioner
model = "gpt-5.3-codex"

# Godkännandepolicy
approval_policy = "unless-allow-listed"

# Sandbox-läge
sandbox_mode = "workspace-write"

# Fallback-filnamn (om projektet redan har annan namnkonvention)
project_doc_fallback_filenames = ["TEAM_GUIDE.md", ".agents.md"]
project_doc_max_bytes = 65536

# Feature flags
[features]
shell_snapshot = true

Ett realistiskt arbetsflöde

Styrkor & Stolthet

Här går vi igenom ett komplett arbetsflöde: från att beskriva en feature, till att agenten implementerar och testar den. Scenariot: ni ska lägga till en ny API-endpoint för att hantera projektinbjudningar.

1

Ge kontext med @-referenser

Öppna relevanta filer och referera dem direkt i prompten. Codex förstår @filnamn-syntax.

Prompt Codex-chatten i VSCode 
Skapa en ny API-route POST /api/projects/[id]/invite som:
1. Validerar input med zod (email, role)
2. Kontrollerar att användaren har admin-roll i projektet
3. Skapar en invitation i databasen med 72h expiry
4. Skickar ett mail via @src/lib/email.ts

Följ samma mönster som @src/app/api/projects/[id]/members/route.ts
Lägg till tester enligt @src/lib/__tests__/members.test.ts
2

Välj rätt mode

Använd Agent mode (standard) för de flesta uppgifter. Codex läser filer, skapar kod och kör kommandon, men frågar innan den skriver utanför workspace eller gör nätverksanrop.

3

Steer medan agenten arbetar

Tack vare mid-turn steering (nytt i feb 2026) kan du skicka meddelanden medan Codex arbetar. Tryck Enter för att styra direkt, eller Tab för att köa input.

4

Granska, iterera, committa

Codex visar en diff-preview av alla ändringar. Acceptera, be om justeringar, eller kör /review för att låta agenten granska sin egen kod. Skapa en Git-checkpoint innan och efter.

De tre agentlägena

Läge Filåtkomst Kommandon Godkännande
Chat Inga Inga —
Agent Läs + skriv i workspace Ja, i workspace Frågar vid nätverks-/extern åtkomst
Agent (Full Access) Full Full + nätverk Inget — var försiktig
⚠️

Skapa alltid en Git-checkpoint innan ni ger Codex en större uppgift. Agenten kan modifiera många filer — git stash eller en feature-branch ger er en enkel väg tillbaka.

5

Vanliga problem och lösningar

Utmaningar & Lösningar

Agentisk utveckling är kraftfullt men inte friktionsfritt. Här är de vanligaste fallgroparna vi sett — och hur ni tar er förbi dem.

Problem Orsak Lösning
AGENTS.md ignoreras Filen är tom, eller Codex hittar inte Git-roten Kör codex status för att verifiera workspace root. Kontrollera att filen har innehåll.
Windows: permission-errors Sandbox kan inte skydda mappar med Everyone-write Flytta repot till WSL: ~/code/repo. Undvik /mnt/c/.
Agenten "spinner" utan resultat Reasoning effort för hög + komplex prompt Sänk reasoning effort till medium. Bryt ned uppgiften i mindre steg.
Rate limit nått Komplexa sessioner förbrukar fler tokens Byt till GPT-5.1-Codex-Mini för enklare tasks. Håll AGENTS.md koncis. Kolla /status.
Testerna passerar lokalt men inte i CI Nätverksåtkomst blockerad i Agent mode Tester med nätverksberoende kräver Agent (Full Access) eller markera dem som skip i AGENTS.md.
Fel modell i extensionen Gammal version av extensionen Uppdatera: Extension-panel → Codex → ⟳. Kontrollera model selector under chatten.

När Codex inte är rätt verktyg

Codex Local briljerar på kodgenerering, refaktorering, testskrivning och buggfixar. Däremot är det inte en ersättning för arkitekturbeslut, säkerhetsgranskningar eller förvaltning av affärskritiska system. Som en senior-ingenjör på LinkedIn uttryckte det: AI förändrar hur vi bygger system, men den upphäver inte behovet av förståelse, omdöme och ansvar.

Avancerade funktioner & ekosystem

Nästa nivå

Codex är mer än en chatbot i editorn. Här är funktionerna som lyfter det från verktyg till arbetsflödesplattform.

🧩 Skills — installerbara agentfärdigheter

Skills är mappar med en SKILL.md och stödfiler som utökar agentens kapacitet. Ni kan installera publika skills, skapa egna, eller dela dem i teamet. Skills aktiveras med $skill-name i prompten eller automatiskt baserat på uppgiften.

  • Personliga: ~/.codex/skills/
  • Projektgemensamma: .codex/skills/ i repot
  • Inbyggda: $skill-creator, $skill-installer

☁️ Codex Cloud — delegera till bakgrunden

Direkt från IDE-extensionen kan ni skicka större uppgifter till Codex Cloud. Agenten jobbar i en sandboxad kopia av ert repo medan ni fortsätter med annat. Resultaten granskas som en diff och kan appliceras lokalt.

🔗 MCP-servrar — integrera externa verktyg

Codex kan konsumera och agera som MCP-server (Model Context Protocol). Det innebär att ni kan koppla in databaser, API-dokumentation, Jira, Slack eller egna verktyg som kontextkällor.

🤖 Automations — agenten jobbar utan prompt

Med Automations kan Codex triggas automatiskt av events — issue triage, CI/CD-status, pull request-reviews, alertövervakning. Tagga @codex i en GitHub PR-kommentar för att starta en code review.

Slash-kommandon i IDE:n

Kommando Funktion

Pro $200/mån 300–1 500 Opt-out tillgänglig

Enterprise Anpassad Flexibel, utökad Aldrig + avancerade kontroller
💡

Optimera era limits: Håll AGENTS.md koncis, minimera antalet MCP-servrar, var precis i prompter utan onödig kontext, och byt till GPT-5.1-Codex-Mini för enklare uppgifter.

⚠️

Business-planen garanterar att er data aldrig används för att träna OpenAI:s modeller. Det är den största skillnaden mot Plus/Pro — och anledningen till att den rekommenderas för företagskritisk utveckling.

Modeller — vad ni ska välja

Aktuellt · Feb 2026

Modelllandskapet rör sig snabbt. I februari 2026 är GPT-5.3-Codex den senaste och mest kapabla agentmodellen. Här är en översikt av relevanta modeller:

Modell Styrka Hastighet Rekommendation
GPT-5.3-Codex Starkast reasoning + kodning 25% snabbare än 5.2 Default för komplexa uppgifter
GPT-5.2-Codex Utmärkt kodning, beprövad Bra Fallback vid API-key-flöden
GPT-5.1-Codex-Mini Kostnadseffektiv Snabb Enkla tasks, sparar rate limits
GPT-5.2 Generalist Bra Bredare reasoning, inte kodspecifik

Byt modell mitt i sessionen via model selector i IDE:n, eller med /model. Reasoning effort (low/medium/high) påverkar tokenförbrukning markant — börja på medium och höj bara vid behov.

Checklista: redo att köra

Sammanfattning

Innan ni börjar

  • ☐ ChatGPT Business-konto aktiverat med Codex-åtkomst (kolla RBAC)
  • ☐ VSCode med Codex-extensionen installerad och inloggad
  • ☐ AGENTS.md i projektets rot med testkommandon och kodstandard
  • ☐ Git-branch eller stash före varje agentsession
  • ☐ Reasoning effort satt till medium som default
  • ☐ Modell: GPT-5.3-Codex (kontrollera att extensionen är uppdaterad)

Första veckans mål

  • ☐ Dag 1–2: Kör genom setup-guiden ovan med ett verkligt projekt
  • ☐ Dag 3: Skriv AGENTS.md med hjälp av Codex ("Analysera detta repo och föreslå en AGENTS.md")
  • ☐ Dag 4–5: Implementera en mindre feature end-to-end med Agent mode
  • ☐ Vecka 1: Testa Codex Cloud med en större refaktorering

AI-skiftet pågår. Modellerna blir bättre var fjärde till åttonde vecka. Det enda sättet att hänga med är att börja använda verktygen på riktigt — inte läsa om dem. Öppna editorn, skapa en AGENTS.md, och ge agenten sitt första uppdrag. Ni har redan licensen.
